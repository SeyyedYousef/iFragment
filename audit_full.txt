۴. ingest فروش میتواند listing را بهعنوان فروش قطعی ثبت کند
در sync زنده صفحه Fragment با regex خوانده میشود. اگر ساختار HTML تغییر کند یا قیمت listing قبل از sale price پیدا شود، همان مقدار ممکن است فروش تشخیص داده شود.
سپس این رکورد با مشخصات زیر ذخیره میشود:
price_confidence = exact transaction_hash = fragment_sale_<timestamp>
این transaction hash واقعی نیست. خطر اصلی این است که NV Engine همین داده را بهعنوان فروش قطعی استفاده کرده و قیمت را anchor کند.
نتیجه: یک parsing اشتباه ممکن است قیمت یک شماره را برای همیشه بالا نگه دارد.
اقدام لازم: فقط event نهاییشده زنجیره با tx hash واقعی، item address، buyer، seller، amount، action index، block و قرارداد بازار وارد جدول verified sales شود.
۵. مصرف Intel Credit و ذخیره گزارش اتمیک نیست
در مسیر پرداخت با coin، کسر موجودی و ذخیره گزارش در یک transaction انجام میشود که خوب است.
اما در مسیر Intel Credit:
کریدت در یک transaction مستقل کم میشود.
الگوریتم اجرا میشود.
ذخیره گزارش بهصورت best effort انجام میشود.
خطای ذخیره گزارش نادیده گرفته میشود.
پس ممکن است کریدت کاربر کم شود، اما entitlement یا گزارش ذخیره نشود.
اقدام لازم: یا همه مراحل در یک transaction قرار بگیرند، یا saga داشته باشید:
reserve credit create pending entitlement compute save report commit entitlement
در هر failure باید refund خودکار و قابل حسابرسی انجام شود.
