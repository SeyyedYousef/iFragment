# 🗄️ پایگاه داده، ساختار مایگریشن‌ها و لایه کَش — Database & Migrations

پایگاه داده اصلی **iFragment** شامل **PostgreSQL 17** به عنوان پایگاه داده رابطه‌ای تراکنشی (ACID) و حافظه موقت پرسرعت چندنخی **DragonflyDB** (سازگار با Redis) برای کَشینگ و مدیریت نشست‌ها است.

---

## ⚠️ قوانین حیاتی مایگریشن‌ها (The Database Invariants)

> [!CAUTION]
> مایگریشن‌های پایگاه داده به صورت خودکار هنگام روشن شدن کانتینر API (`cmd/api`) اجرا می‌شوند.
> هرگونه خطایی در اجرای اسکریپت مایگریشن، بی‌درنگ منجر به **Crash-Loop شدن کانتینر در سرور پروداکشن** می‌شود!

### ۵ اصل طلایی نگارش فایل‌های SQL مایگریشن:
1. **Idempotency مطلق (تکرارپذیری بدون خطا):**
   - ایجاد جداول با `CREATE TABLE IF NOT EXISTS`
   - ایجاد ستون‌ها با بررسی شرطی یا بلوک `DO $$ BEGIN ... END $$;`
   - ساخت ایندکس‌ها با `CREATE INDEX IF NOT EXISTS`
2. **عدم فرض پیشینی بر وجود جداول یا توابع (No Implicit Assumptions):**
   - حادثه تاریخی ۲۰۲۶-۰۸-۲۵: مایگریشن `000070` فرض کرده بود جدول `sales` ایجاد شده و کانتینر پروداکشن متوقف شد. همیشه قبل از `ALTER` یا کلید خارجی، وابستگی‌ها اعتبارسنجی شوند.
3. **تقارن فایل‌های `.up.sql` و `.down.sql`:**
   - هر تغییر در جهت ارتقا، باید دارای رول‌بک دقیق و تمیز در جهت معکوس باشد.
4. **ترتیب‌گذاری ایمن ایندکس‌ها برای کوئری‌های مقیاس‌بالا:**
   - تمام ستون‌های مورد استفاده در `ORDER BY` و فیلترهای لیدربورد یا سرچ پترن‌ها باید ایندکس ترکیبی مناسب داشته باشند.
5. **جداسازی تراکنش‌های مالی و کنجکاوی:**
   - تراکنش‌های کسر کریدیت باید درون تراکنش اتمیک (`BEGIN ... COMMIT`) همراه با چک `balance >= required` انجام گیرند.

## 🗃️ ساختار و شِمای جداول کلیدی (Core Database Schemas)

| نام جدول در دیتابیس | هدف و دامنه کاربرد | جزئیات فنی و ستون‌های حیاتی |
| :--- | :--- | :--- |
| `users` | اطلاعات احراز هویت تلگرام | `telegram_id` (BigInt PK)، زبان، رول (owner/user)، تاریخ آخرین ورود |
| `user_profiles` | نمایه کامل و استیت‌های مالی | موجودی کریدیت، والت‌های متصل TON، سطح کاربری (Tier) |
| `fragment_investors_user_stats` | لیدربورد سوپرگروه و بوست‌ها | `user_id` (PK)، `message_count`، `boost_count`، `photo_url`، `updated_at` |
| `fragment_investors_raffle_tickets` | بلیت‌های قرعه‌کشی دوره‌ای | رویدادهای چت، کد بلیت، تاریخ انقضا و وضعیت برنده |
| `telegram_webhook_inbox` | صف ایونت‌های ورودی تلگرام | ثبت رویدادهای خام آپدیت تلگرام با مکانیزم جلوگیری از رویداد تکراری (Idempotency) |
| `auctions` | مزایده‌های فرگمنت | نام دارایی، نوع (یوزرنیم/شماره)، آخرین بید (TON)، زمان انقضای حراج |
| `sales` | تاریخچه فروش‌های قطعی | ثبت قیمت تحقق‌یافته جهت لنگر انداختن حداقل ارزش موتورهای AVM و NV |
| `gifts` | دارایی‌های دیجیتال TEP-62 | مدل گیفت، شماره صدور (`num`)، درصد رریتی، متادیتای ویژگی‌ها (Traits JSON) |
| `intel_credits_batches` | بسته‌های کریدیت خریداری‌شده | سهمیه کنجکاوی کاربر، تاریخ انقضا، نوع بسته (Free, Boost Bonus, Bought) |
| `intel_credit_transactions` | دفترکل تراکنش‌های کسر کریدیت | آیدی تراکنش، دلیل استعلام (ارزیابی یوزرنیم/گیفت/شماره)، زمان کسر |
| `managed_userbots` | استخر یوزربات‌های تله‌تون | نشست‌های پایتون (`session_string`)، وضعیت فعال، نرخ ریت‌لیمیت تلگرام |
| `audit_logs` | لاگ امنیتی اقدامات اونر | عملیات حساس، کد TOTP استفاده‌شده، آی‌پی، زمان و پارامترهای تغییر کانفیگ |
| `ads` & `promos` | بنرهای تبلیغاتی و کدهای تخفیف | محل بنر، نرخ کلیک، ایمپرشن‌ها، کدهای هدیه و دفعات استفاده |

## ⚡ لایه کَش با DragonflyDB (سازگار با Redis)

موتور **DragonflyDB** جایگزین مدرن و چندنخی Redis است که تا ۲۵ برابر توان پردازش بیشتر و مصرف رم بسیار کمتری ارائه می‌دهد:

### کلیدهای پرکاربرد در حافظه موقت:
- `cache:auctions:live` — لیست مزایده‌های داغ فرگمنت (کش ۵ ثانیه‌ای)
- `cache:rates:ton_usd` — نرخ لحظه‌ای TON به دلار آمریکا
- `cache:rates:stars_ton` — نرخ برابری تلگرام استارز به تون
- `session:user:{tg_id}` — نشست‌ها و توکن‌های تأییدشده ورود کاربر
- `cache:leaderboard:messages:top100` — کش سریع رتبه‌بندی پیام‌های سوپرگروه
- `cache:leaderboard:boosts:top100` — کش سریع برترین حامیان و بوسترهای کانال
